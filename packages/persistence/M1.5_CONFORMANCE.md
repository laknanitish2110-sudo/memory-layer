## Hardening Actions Taken

1. **Migration 007_force_rls.sql** — `FORCE ROW LEVEL SECURITY` on all 8 memory tables
2. **Migration 007_force_rls.sql** — `REVOKE ALL` on all memory + credential tables from `anon` role
3. Both applied to live Supabase instance and committed as migration

## Architecture Notes for M2

1. **API must use `authenticated` role** — never `service_role` or `postgres` for user requests
2. **`app.passport_id` must be set by trusted backend code only** — the session variable is the security boundary
3. **Service_role bypasses RLS by design** — restrict to admin/migration operations
4. **Defense in depth is working**: Kernel authorization + Repository boundary + Database enforcement
